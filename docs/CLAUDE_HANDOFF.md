## 현재 작업 — 네이티브 FBX

사용자의 “아니 앱에 하라고”에 따라 앞선 웹 FBX 작업은 대상 오해로 철회했습니다. [웹 PR #3](https://github.com/yonddu/3d-hand/pull/3)은 **닫힘·미병합**이며 배포 후보로 제안하지 않습니다. 해당 작업 이력은 [기존 기록](handoffs/2026-10-29-fbx-export.md)에 보존합니다.

Android 측정 앱에 **FBX 저장** 버튼을 추가했습니다. 기록을 중지한 뒤 .fbx를 Android 파일 선택기로 저장합니다. 원본 21관절 위치 애니메이션으로, 손 메시나 고정 길이 게임 리그·본 회전·절대 카메라 이동 복원이 아닙니다. 기존 JSON 저장과 원본 추적은 유지합니다. Android 빌드·JVM 테스트·Lint·독립 FBX 재읽기 PASS(합성 위치 오차 최대 6.87519688e-09m). 실제 휴대폰 저장/게임엔진 확인 전입니다. 상세/검증/APK 링크는 [네이티브 FBX 기록](handoffs/2026-10-29-native-fbx-export.md)을 읽으세요.

## 네이티브에 대한 사용자의 결정

- 원본 네이티브 MediaPipe 관절점 추적은 추가한 3D 손보다 훨씬 잘된다고 평가했습니다.
- 원한 것은 기존 웹에서 자연스럽던 손·손목·팔 동작을 재사용하는 것이었습니다.
- 별도 리타게팅 구현(v0.3/0.4)을 거절했고, 실제 웹 `main.js`를 사용하는 재시도(v0.6)도 직접 확인 후 **“다시 되돌려 또 엉망이네”**라며 거절했습니다.
- 따라서 **현재는 3D 손·팔·WebView Studio를 제거한 측정 앱만 유지**합니다. 추가 개선 작업은 새 사용자 지시가 있어야 재개합니다.
- **항상 작업 종료 시 Claude 인계 자료를 만들고 기록**하라는 지시를 AGENTS.md와 CLAUDE.md에도 남겼습니다.

## 현재 앱에 있는 것 / 없는 것

- CameraX 후면 카메라, MediaPipe HandLandmarker 0.10.21, 기존 hand_landmarker.task.
- GPU 요청 기본값, CPU 수동 비교, 최대 한 손/두 손 비교(기본 두 손), 원본 21점 표시와 JSON 기록, 원본 관절 위치 FBX 저장.
- **3D 손·팔, WebView Studio, 별도 손가락 추정, GLB 저장 UI 없음.** 기존 웹앱의 GLB 기능 자체를 삭제한 것은 아닙니다.
- NPU 미적용, 전처리는 Bitmap 복사·자르기·회전이며 zero-copy가 아닙니다.
- 사용자 기기: SM-S931N. 최초 측정 Android 16, 가장 최근 첨부 화면은 **Android 17**입니다.

## 검증 결과와 제한

- v0.7 롤백 APK의 Android 빌드·JVM 테스트·Lint PASS 및 원본 복원 확인은 과거 결과입니다. v0.8 검증은 새 네이티브 FBX 기록을 참조하세요.
- 기존 v0.6도 CI/브라우저 테스트는 통과했지만 **실제 사용자 화면에서는 실패**했습니다. 이 사실이 최종 판단입니다. 3D 문제가 해결됐다고 표현하면 안 됩니다.
- 원본 측정 화면 수치(서로 다른 순간, 통제된 비교 아님): GPU 14.1 FPS / 추론 p50 49.3ms, CPU 11.9 FPS / 추론 p50 69.9ms. 실제 GPU 사용률이나 정확도 입증이 아닙니다.
- 전체 `npm run regress`는 **실패**입니다. 23개 제공 GLB에서 지표 한도 초과는 없지만 기준 JSON 18개가 빠졌고, holdout 둘 다 누락되어 holdout 검증은 0개입니다.
- 누락: `raw_take2.json`…`raw_take17.json`, `raw_w2take2.json`, `raw_w2take3.json`.
- 마지막 23개 합계는 변경 전과 동일: swap13, flip154, jump3639, gsw308, fjump442, fflip5, asnap10, unsure12111.
- 누락 파일 제외, 한도 상향, `--accept`, score-only 튜닝 금지. 전체 데이터·회귀가 준비되기 전 PR #2 병합 금지. 인계 문서만 main에 기록하는 것은 네이티브 코드 병합이 아닙니다.

## 설치 관련

- CI debug 서명이 고정되지 않아 기존 앱 위 업데이트가 실패할 수 있습니다. 필요 기록을 저장한 뒤 기존 측정 앱을 제거하고 재설치하는 방식으로 사용했습니다.
- 삼성의 “잠재적으로 유해한 앱 감지됨 / 피싱 시도 후에 설치되었습니다” 경고가 실제로 나왔습니다. 서명 충돌과는 별개입니다.
- 삼성 담당자의 공개 안내에서 외부 설치 앱 경고와 개별 앱 실행 경로를 확인해 안내했으나, APK의 무해함을 완전히 감사했거나 보안 경고를 코드로 해결한 것은 아닙니다. 전체 보안 해제를 해결책으로 삼지 마세요.

## 이어받을 때

1. 원본 측정 앱을 유지하고, 사용자가 새 작업을 지시하기 전 3D 재시도를 하지 않습니다.
2. 향후 재개하더라도 실제 원본 영상·동일 시점 관절값·3D 결과를 함께 비교해야 합니다. 이전 두 시도의 실제 실패 원인은 확정되지 않았습니다.
3. 기존 웹이 사용자가 말한 “자연스럽던 버전”과 동일한 버전인지도 확인이 필요합니다. 최신 main을 재사용하는 것만으로 해결된다고 단정하지 않습니다.
4. 과거 렌더 기반 손가락 모델/128 실험 및 되돌린 수정은 `docs/improve/`를 먼저 확인합니다. 과거 라벨 CSV도 사용자에게 엄지 가시성 오류 지적을 받아 검증된 정답으로 취급하면 안 됩니다.
5. 다음 작업 종료 전 이 문서와 날짜별 이력을 반드시 갱신합니다.
