# 2026-10-29 — 웹 FBX 내보내기 추가 인계

## 요청과 범위

사용자 요청: **“glb말고 fbx파일로도 만들수있게 해봐.”**

기존 웹 Studio에 FBX 파일 저장을 추가했습니다. 앞서 거절·롤백한 네이티브 3D 손·팔을 복구하지 않았고, 원본 측정 APK v0.7/PR #2의 코드도 변경하지 않았습니다.

- 위 데모 파일은 테스트용 가상 동작이며 사용자의 실제 손 녹화나 정답 데이터가 아닙니다.

## 구현

1. 리뷰에서 GLB/FBX 형식을 선택한 후 저장합니다. 기본값은 기존 GLB입니다.
2. 저장된 포즈 목록에도 FBX 버튼을 추가했습니다.
3. 기존 `src/exportGlb.js`의 장면 생성을 `buildMotionScene`로 분리했습니다. GLB/FBX가 같은 스킨 메시, 본 이름/계층/길이, 시간, 손·팔·손목·손가락 애니메이션을 사용합니다.
4. `src/exportFbx.js`는 브라우저에서 바이너리 FBX 7.4를 생성합니다. 외부 서버/유료 서비스/Autodesk SDK가 없고 런타임 의존성도 추가하지 않았습니다.
5. FBX의 스킨 클러스터에는 mesh-to-bone 바인드 행렬과 본의 bind-to-world 행렬을 구분해 기록합니다. 독립 로더 검사 중 초기 행렬 오류를 발견해 수정했습니다.
6. FBX Euler 회전 곡선은 원래 quaternion 보간을 샘플링해 작성합니다. 원본 관절 계산이나 움직임 보정이 아니라 저장 형식 변환입니다.
7. 단일 포즈는 재생 전에도 저장 자세로 열리도록 기본 변환을 기록합니다. 움직이는 클립은 숨겨진 손의 0 스케일로 임포터 초기 변환이 퇴화하지 않도록 바인드 기본값과 애니메이션 곡선을 사용합니다.
8. 파일명/확장자/MIME, artifact ZIP 경로를 GLB/FBX 모두 처리하도록 했습니다.
9. 추적·solver·lift·fit·filters·팔·메시 리깅·회귀 기준은 변경하지 않았습니다.

예상 효과를 수정 전에 안내했습니다: 같은 장면을 다른 파일 형식으로 저장하며 포즈 지표는 그대로여야 합니다. 저장 시에만 변환하고 minified 앱 번들 증가량은 약 10.8KB(압축 전)입니다. FBX 파일 자체는 미압축 배열을 포함해 GLB보다 클 수 있습니다.

## 검증

최종 기능 코드 CI의 export job **PASS**:

- Node + three.js FBXLoader: 바이너리/스킨 메시/51개 본/애니메이션/단위/샘플 변환 검사.
- 시험 동작의 회전 차이 최대 약 0.0091도, 본 위치 차이 약 4.7e-8m.
- 독립 **MIT ufbx** strict importer + 실제 스킨 변형 평가:
  - 동작 8개 시점 × 85,658 정점, 최대 오차 **3.57236778e-5m (약 0.036mm)**.
  - 단일 포즈 1개 시점 × 85,658 정점, 최대 오차 **3.60644325e-8m**.
- 단일 포즈가 재생 전 저장 자세로 열리는지 검사.
- 브라우저 실제 리뷰 GLB/FBX 선택·다운로드, 포즈 FBX 버튼, 스킨·애니메이션·360px 화면 레이아웃 검사.
- 기존 `tools/test-export-hide.mjs` PASS (GLB 손 표시/숨김 유지).
- `node build.mjs`와 커밋된 빌드 결과 일치 PASS.

이 검증은 **파일 형식 변환**에 대한 것입니다. 실제 손 추적 정확도나 기존 3D 문제 해결을 의미하지 않습니다. 실제 Blender/Unity/Unreal 앱을 직접 열어 수동 확인한 것은 아닙니다. FBX는 기본 재질 색상/스킨/본/애니메이션을 지원하며, GLB의 원본 추적 extras나 가상 카메라는 넣지 않습니다.
