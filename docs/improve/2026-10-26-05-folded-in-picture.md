# 개선 5: 그림에서 접힌 손가락이 펴진 것으로 나옴 (사용자 신고 영상의 약지·새끼)

## 1. 점수 (v77)
새 지표 openpic = 그림에서 손끝이 손가락 뿌리보다 손목 쪽에 있는데(접힌 손가락) 결과의 둘째+셋째 마디 굽힘이 60도 미만.
실제 채점용(w2): openpic 303, bentpic 13, fjump 33, jump 196.  개발용: openpic 1161, bentpic 431, fjump 434.
가상 채점용 관절 각도 오차 20.50도.
규칙 검증(가상 개발용): "손끝이 뿌리보다 손바닥 0.05 이상 손목 쪽" 이면 실제로 손가락 전체 굽힘 90도 이상인 경우가 90%.

## 2. 유형
clasp_same_14-10.glb 8.5~9.0초: 접은 약지·새끼가 7~46도로 펴져 보임. 깊이(앞뒤 기울기) 선택이 펴진 쪽을 고름.

## 3. 고치기 전 예상
- 수정: lift.js 깊이 조합 고르기에서, 그림상 손끝이 뿌리보다 손목 쪽인 손가락은 전체 굽힘 90도 미만 조합에 벌점.
- 채점용 openpic 303 -> 약 200, 개발용 1161 -> 약 800.
- 가상 채점용 오차 20.50 -> 20.1~20.4.
- 채점용 fjump 33 -> 30~45 (조합이 바뀌는 순간 튈 수 있음). 나빠지면 되돌림.

## 4~6 (첫 시도). lift.js 깊이 조합 벌점
채점용 openpic 303 -> 298, fjump 33 -> 40 (나빠짐), 개발용 그대로, 가상 20.50 그대로. 되돌림.
원인을 다시 추적: 약지는 깊이 단계(lift)에서 이미 접혀 있음(뿌리 60~80, 둘째 55~77도).
펴지는 곳은 그 다음: 약지가 다른 손가락 뒤에 가려졌다고 판단돼서(가림 1.0) 읽은 값을 버리고
데이터 손모양을 따르는데, 손모양을 고를 때 보이는 손가락만 봐서 "검지만 구부림" 모양(약지·새끼 폄)을 고름.

## 3 (다시 예상). 손모양 고를 때 가려진 관절도 약하게 반영
- 수정: gripPrior misfit에서 가려진 관절 가중치 0 -> 0.3 (읽은 값도 약한 증거로).
- 채점용 openpic 303 -> 약 220, fjump 33 -> 30~45.
- 가상 채점용 20.50 -> 20.0~20.4.

## 4~6 (두번째 시도). 결과
- 채점용: openpic 303 -> 303 (변화 없음), fjump 33 -> 32, jump 196 -> 216 (나빠짐).
- 개발용: openpic 1161 -> 654, bentpic 431 -> 478, fjump 434 -> 570.
- 가상 채점용: 20.50 -> 20.46, 접힌 관절 -31.8 -> -34.4 (나빠짐).
- 판정: 예상(채점용 openpic 약 220)에 못 미치고 채점용 jump가 나빠짐 -> 되돌림.
- 개발용에서만 좋아진 것은 그 영상(같은 자세 양손)에 맞춘 효과일 가능성이 큼. 채점용에 안 보이면 채택하지 않음.
- 다음: 같은 유형을 규칙으로 더 밀면 도돌이표 위험. 1단계의 다른 유형(깍지 때 좌우 뒤바뀜)으로 넘어감.
