# 개선 3: 많이 구부린 손가락이 덜 구부러져 보임 (가상 데이터 채점)

채점 기준(사용자 결정 13:31): 관절 각도 오차는 가상 데이터 채점용 묶음(seed 2, 개발 중 안 봄)으로,
실제 채점용 영상(w2)은 안전장치(나빠지면 무조건 되돌림).

## 1~2. 측정과 유형 (가상 개발용 묶음 seed 1, 손 찾은 약 560장)
앱 관절 각도 기준 평균 오차 20.2도. 가장 큰 유형: 실제 80~100도 구부린 둘째 마디가 평균 45도 덜 구부러짐.
원인 추적:
- MediaPipe 원본 3D를 그대로 넣어도 같은 문제(평균 22.7도, 둘째 마디 -48도). 우리 단계는 오히려 조금 줄임(22.7 -> 20.2).
- 깊이 방향 선택을 정답으로 바꿔도(오라클) -34도까지만 좋아짐. 뼈 길이를 바꿔도 효과 없음.
- MediaPipe의 2D 점 자체가 많이 구부린 손가락에서 손바닥 길이의 0.25~0.33만큼 틀림(손끝을 더 펴진 곳에 찍음).
=> 입력(MediaPipe)이 틀리는 문제라, 고칠 수 있는 길은 "보이지 않는 관절은 데이터 손모양을 따른다"를 넓히는 것뿐.

## 3. 고치기 전 예상
- 수정: 손등이 보일 때만 쓰던 "손가락 관절이 주먹 안에 숨음" 판단을 손 방향과 관계없이 쓰기 (손가락 뿌리가 35~70도 이상 굽으면 끝 두 마디는 데이터 손모양을 따름).
- 가상 채점용: 평균 오차 -0.3~-0.5도 (개발용에서 20.15 -> 19.79). 작은 효과.
- 실제 채점용: 튐(jump/fjump) 비슷하거나 약간 증가할 수 있음 (가려진 손가락 프레임에서 튐이 많았음). 나빠지면 되돌림.

## 4. 수정
fit.js hiddenJoints: tucked 판단에서 손등 방향 조건 제거 (손가락 뿌리 35~70도 이상 굽으면 끝 두 마디는 데이터 손모양을 따름).

## 5. 다시 채점
가상 채점용(seed 2, 손 찾은 304장): 관절 각도 오차 20.46 -> 20.50도 (+0.04, 사실상 그대로).
  많이 구부린 손가락 마디(60도 이상): -34.3 -> -31.8도 (2.5도 덜 틀림).
가상 개발용(seed 1): 20.1 -> 19.7도.
실제 채점용 안전장치(w2): jump 303 -> 196, fjump 198 -> 33, gsw 21 -> 17, flip 9 -> 9 (나빠진 것 없음, 튐 크게 감소).
실제 개발용: jump 5206 -> 4098, fjump 4595 -> 2018. 알려진 문제 8개 모두 통과.
예상(전체 -0.3~-0.5도)과 비교: 전체 오차는 줄지 않음. 고른 유형(구부린 손가락)만 2.5도 좋아짐.

## 6. 결과
판단 보류: 규칙대로면 전체 점수가 안 좋아졌으니 되돌림. 다만 실제 영상 튐이 83% 줄어 사용자에게 확인 요청.
