# 19. 접힌 손가락이 펴지는 문제 (2026-10-27)

## 단계별 측정 (개발용 렌더 seed11, 앱과 같은 굽힘·큐브 모델, 접힌 PIP/DIP 관절 1816개 = 정답 60도 이상)
| 단계 | 펴짐(30도 미만)으로 읽음 | 뒤로 꺾임(-10도 미만) |
|---|---|---|
| MediaPipe 입체 점 | 632 (34.8%) | 383 |
| lift 뒤 | 634 (34.9%) | 269 |
| fit 뒤 (최종) | 343 (18.9%) | 0 |
최종 펴짐 343개의 출처: lift가 이미 펴서 넘김 137, lift가 뒤로 꺾어 fit이 가동 범위로 잘라 펴짐 121, lift는 맞았는데 fit이 편 것 85.

원인 확인: lift는 손가락 세 뼈의 깊이 방향 8조합 중 "MediaPipe 입체 점의 관절 굽힘 크기와 맞는 것"을 고르는데,
굽힘을 방향 없이(크기만) 비교함. 뒤로 90도 꺾인 조합과 앞으로 90도 접힌 조합이 같은 점수가 됨.

## 수정 1 예측 (채점 전에 씀)
lift 조합 선택에 관절 방향을 넣음: 검지~새끼의 MCP/PIP/DIP가 가동 범위 최소(0도)보다 15도 넘게 뒤로 꺾이는 조합에 비용.
- 개발용 seed11: lift 뒤로 꺾임 269 -> 100 아래, 최종 펴짐 343 -> 290 안팎.
- 채점 전용 관절 각도 오차: 한손 seed10 17.31 -> 17.1 안팎, 양손 17.31 -> 17.1 안팎.
- 실제 held-out 테이크(jump 200, fjump 33): 나빠지지 않음(손가락 깜빡임이 줄면 약간 좋아질 수도).
유지 기준: 채점 전용 둘 다 좋아지고 held-out이 나빠지지 않을 때만.

## 결과 (수정 1)
| | 개발 seed11 lift 뒤로 꺾임 / 최종 펴짐 | 채점 한손 seed10 | 채점 양손 | 실제 held-out (jump / fjump) |
|---|---|---|---|---|
| 지금 main | 269 / 343 | 17.31 | 17.31 | 200 / 33 |
| 수정 1 (규칙 항상) | 124 / 316 | 16.81 | 15.97 | **402 / 181** |
| 수정 1b (손가락 2개 이상 뒤로면 규칙 끔) | 233 / 337 | 17.29 | 17.33 | 200 / 33 (개발 테이크 34개 기준 초과) |
렌더 점수는 예측보다 더 좋아졌지만, 실제 영상 held-out이 두 배로 나빠짐 -> 규칙대로 되돌림.
원인 조사: 실제 테이크에서 방향 부호는 맞음(크게 굽힌 관절의 74~92%가 손바닥 쪽). 나빠진 이유는 손바닥 방향(거울 자세)이
틀린 프레임에서는 진짜 접힘이 전부 "뒤로 꺾임"으로 보여서, 규칙이 손바닥 선택과 프레임마다 싸우며 손가락을 흔듦.
1b처럼 그런 프레임에서 규칙을 끄면 렌더에서 얻던 이득도 거의 사라짐 -> 렌더 이득의 대부분이 손바닥 방향이 틀린 경우였음.
결론: "여러 손가락이 함께 뒤로 꺾임"은 손가락 문제가 아니라 손바닥 방향(mirrorPlan)이 틀렸다는 증거. 다음 후보는
이 증거를 손바닥 방향 선택(영상 전체로 고르는 mirrorPlan)에 넣는 것. 손가락 하나만 뒤로 꺾이는 경우는 그다음.
