# 20. 다른 손 위에 생긴 유령 손 (2026-10-27)

**신고.** left_pop_20-47.glb, "10초쯤 갑자기 왼손이 튀어나옴".

**원인.**
- MediaPipe가 오른손을 한 번 더 읽어 "왼손"으로 냈어요(원본 8.24초 2프레임, 11.94~12.86초 13프레임).
- 상자가 오른손 상자 안에 85~100% 들어가 있고, 점 평균 거리는 손바닥 0.27~0.49예요. 중복 제거 문턱 0.3을 대부분 넘어서 살아남았어요.
- GLB 저장은 손이 처음 보이기 전과 마지막으로 보인 뒤를 가장 가까운 프레임으로 채워요. 그래서 0.9초짜리 유령이 영상 전체에 서 있었어요.

**측정 추가.** replay에 `inside` 표시를 넣었어요. 두 손이 남았는데 작은 손 상자의 80% 이상이 다른 손 상자 안에 있는 프레임 수예요. 진짜 포갠 손에서도 생기므로 신고 영상에만 한도를 걸어요.

수정 전 inside: left_pop 11, two_hands_03-59 86, clasp_same 22, shaky 17, ref_23-01 4, 나머지 0.
수정 전 regress: dev swap 57 flip 180 jump 5897 gsw 335 fjump 2508 fflip 2 asnap 100. held-out jump 200, fjump 33.

## 수정 1: 추적 중인 손 상자 안에서 새로 생긴 손은 10프레임 뒤에 받기
**예측 (수정 전에 적음).**
- left_pop: inside 11 -> 0, 왼손 프레임이 모두 사라져 GLB에 오른손만 남음.
- 이미 따로 추적되던 손이 겹치는 영상(two_hands, clasp, interlace)은 거의 그대로. 겹친 채로 새로 들어온 손이 있으면 처음 1/3초가 빠져 inside·hpierce가 조금 줄 수 있음.
- held-out(한 손 영상): 그대로 (jump 200, fjump 33).
- 앱 무게: 프레임당 상자 비교 한 번, 변화 없음.

**결과.**
| | 예측 | 실제 |
|---|---|---|
| left_pop inside | 11 -> 0 | 0 (GLB 왼손 없음) |
| held-out | 그대로 | jump 200, fjump 33 그대로 |
| dev swap / flip / jump | 거의 그대로 | 57 -> 16 / 180 -> 162 / 5897 -> 5867 |
| dev fjump / fflip / asnap | 그대로 | 2508 -> 2519 / 2 -> 3 / 100 -> 102 |

- 예측보다 좋았던 점: shaky_02-46(한 손 영상)에도 20.5초부터 끝까지 가짜 왼손이 있었는데 사라졌어요. ref_23-01, clasp_same, two_hands의 좌우 바뀜도 줄었어요.
- 예측과 다른 점: shaky fjump 61 -> 76(이슈 한도 66). 16.5초와 22초 오른손이에요. 유령이 오른손 이름을 빼앗거나 겹친 손 처리에 끼어들던 프레임이 이제 오른손 실제 읽기로 쓰이면서, 그 안의 깊이 오판이 드러났어요. clasp_same bentpic 102 -> 103(한도 102).
- 처음에는 "추적 위치에서 먼 쪽"을 새 손으로 골랐는데, 유령 손목이 진짜 손목보다 가까운 경우(shaky 16.47초)가 있었어요. 그래서 "추적 중인 손과 다른 이름의 손"을 먼저 새 손으로 봐요.
- 10프레임 넘게 계속 나오는 유령(shaky 6.2~6.9초)은 아직 받아들여요.
- 사용자가 "유지, 두 한도를 새 값으로"를 골라 shaky fjump 한도·기준을 76, clasp_same bentpic 한도를 103으로 바꿨어요.
