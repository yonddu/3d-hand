# improve/31: picture models at 128 crops (2026-10-28)

User asked: raise picture models (finger curl + joint cube) to 128, run them on GPU/WASM, and consider 256 if 128 is much better.

## Prediction (written before training)
Sharper crops help the curl/cube models on renders by a clear margin (curl score-only error down >= 1 deg, cube wrong side down >= 1 point).

## Setup
- Same renders, same steps (8000), same seeds; only crop size differs. HMS_CROP=128 in tools/palm/crops.py, train.py (one more stride-2 layer 16->16 first, augment pixel sizes scaled).
- Curl: train seed3, score-only seed4. Cube: train seed9, score-only seed10.

## Result (score-only)
| model | 64 | 128 |
|---|---|---|
| curl joint error | 13.18 deg | 13.32 deg |
| curl curled joints (60+) | -19.2 off | -19.1 off |
| cube along wrong side | 8.5% | 8.4% |
| cube nail wrong side | 6.0% | 6.3% |

Prediction NOT met: 128 is no better on renders. The limit is not crop sharpness (render hands are ~150-250 px tall, the net is tiny). 256 not tried (no gain from 64->128).
The real problem stays the render-to-real gap (improve/29: real fingers read ~22 deg everywhere). Only real labels can test whether 128 helps on real video (real crops so far are 64 only).
