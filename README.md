# Hand Motion Studio (1단계 프로토타입)

스마트폰/웹캠 카메라로 양손(21관절 x 2)을 추적하고, 랜드마크를 **게임 캐릭터에 바로 쓸 수 있는 관절 회전(쿼터니언)** 으로 바꿔 Three.js 리깅 손 모델에 적용한 뒤, 포즈를 JSON으로 저장/불러오는 웹 앱입니다.

## 실행

빌드된 `index.html`과 `vendor/`(Three.js, MediaPipe wasm, 손 모델)가 모두 들어 있어 인터넷 없이도 돌아갑니다. 정적 서버로만 열면 됩니다.

```bash
npm install        # esbuild 등 개발 도구 (소스를 고칠 때만 필요)
npm run build      # app.html + src/ -> index.html, dist/artifact/
python3 -m http.server 8080   # 또는 npm start
# 브라우저에서 http://localhost:8080
```

- `file://`로 직접 열면 ES 모듈과 wasm이 막히므로 꼭 서버로 여세요.
- **스마트폰 카메라는 HTTPS에서만 열립니다.** 폰으로 쓰려면 GitHub Pages / Netlify / Cloudflare Pages 같은 HTTPS 정적 호스팅에 폴더째 올리거나, PC에서 `npx localtunnel --port 8080` 같은 터널을 쓰세요.
- 촬영(퀘스트3 방식): 폰을 거치대에 세워 **내 눈 높이에서 내가 보는 방향**을 찍게 하고 "후면 카메라"를 고른 뒤, 폰 뒤에서 양손을 앞으로 뻗습니다. 카메라에 손등이 보이고, 3D 화면도 그대로 1인칭(손등) 시점이 됩니다. 전면 카메라/웹캠처럼 카메라와 마주 보는 경우에는 손을 180° 돌려서 같은 1인칭 화면으로 보여 줍니다. 왼손/오른손이 반대로 붙으면 "왼손·오른손 바꾸기"를 켜세요.

## 화면 구성

- **입력**: 데모(카메라 없이 가상 손 데이터를 같은 파이프라인에 흘림) / 카메라 / 동영상 파일
- **시점**: 폰 카메라 = 내 눈 위치인 1인칭 하나. 마우스·터치로 돌려 볼 수 있고 "1인칭 시점으로"로 되돌아갑니다.
- **관절 엔진**: 가동 범위 제한, 떨림 보정(One Euro min cutoff), 반응 속도(beta), 관절 점/원본 랜드마크 비교, 쥔 물건(자동 / 손 모양만 / 원기둥·공·상자·막대 고정 / 끄기), 손가락 접촉 보정, 아래팔·팔꿈치 / 위팔 표시, 손 재질(퀘스트 스타일 / 피부 / 귀신 손)
- **카메라 미리보기**: 손 관절과 함께 인식된 물건 상자(점선, 이름과 확률)가 표시됩니다.
- **관절 각도**: 손가락별 1~3관절 굽힘/벌림 각도(°)와 신뢰도
- **포즈**: 캡처(즉시 / 3초 타이머 / Space), 보기, JSON 저장, JSON 불러오기, 전체 내보내기. 목록은 브라우저 localStorage에 저장됩니다.

## 구조

```
app.html           화면 마크업 + CSS (build.mjs가 index.html로 감쌈)
src/
  skeleton.js      랜드마크 인덱스, 손가락 정의, 관절 제한, 기준 손 비율, 본 이름(Mixamo 규칙)
  tracker.js       MediaPipe Hand Landmarker (VIDEO 모드, 양손, GPU→CPU 폴백, 좌우 판정 정리)
  filters.js       One Euro 필터 (관절 떨림 보정)
  solver.js        랜드마크 → 본 회전 (손바닥 기준 좌표계, 굽힘/벌림 분해, 관절 제한, 신뢰도)
  handRig.js       계산용 리깅 손: THREE.Skeleton(Mixamo 본 이름) + 예비 메시, 포즈 읽기/쓰기
  realHand.js      실제 손 모양 메시(WebXR generic-hand, 퀘스트 계열 관절 구조)를 계산용 리그에 맞춰 움직임
  grasp.js         쥔 물건을 손에 앉히기(카메라 인식 또는 손 모양 추정) + 손끝을 표면에 맞추는 접촉 보정
  objects.js       물체 인식 결과 → 형태 템플릿(컵·병=원기둥, 공·과일=구, 폰·책=상자, 칼·칫솔=막대)과 실제 크기
  arm.js           아래팔·팔꿈치: 포즈 인식으로 보이면 그 위치, 안 보이면 어깨→손목 2관절 IK 추정
  demo.js          가상 손 동작 생성기 (편 손, 주먹, 가리키기, 브이, 귀신 손, 집기)
  pose.js          포즈 JSON 포맷, 로컬 라이브러리
  main.js          씬, UI, 프레임 루프
vendor/            three 0.170.0, @mediapipe/tasks-vision 0.10.21, hand_landmarker.task (float16),
                   efficientdet_lite0.tflite (int8, COCO 물체 인식), pose_landmarker_lite.task (팔꿈치),
                   hand-left/right.glb (@webxr-input-profiles/assets 1.0.20, MIT, LICENSE 동봉)
build.mjs          index.html(독립 실행) + dist/artifact/(claude.ai 데모용) 생성
```

### 관절 회전 계산 방식 (solver.js)

1. 손목(0)·검지 MCP(5)·중지 MCP(9)·소지 MCP(17)로 손바닥 좌표계를 만들어 손목 회전을 구합니다. (+Y 손가락 방향, +Z 손바닥 법선)
2. 각 뼈마다 관측된 방향(자식 관절 − 관절)을 **이미 풀린 부모 뼈의 기준 자세 좌표계**로 옮깁니다.
3. 그 방향을 굽힘(로컬 X축 회전)과 벌림(로컬 Z축 회전) 두 각도로 분해하고, 해부학적 범위로 자릅니다. (예: 손가락 PIP 0~115°, 벌림 0°)
4. 비틀림 없는 회전으로 다시 조립해 `restLocal * swing` 형태의 로컬 쿼터니언을 만듭니다.
5. 뼈 길이가 기준값에서 갑자기 벗어나면(가림, 원근 왜곡) 신뢰도를 낮추고 그 뼈는 더 천천히 따라가게 합니다.

랜드마크 자체는 One Euro 필터로 먼저 떨림을 줄입니다.

### 쥔 물건 (objects.js, grasp.js)

물건 모양을 먼저 알아낸 뒤, 그 표면에 손이 붙는 손 모양을 만듭니다. (손목 기준 좌표계: +Y 손가락 방향, +Z 손바닥 바깥)

1. **카메라 인식**: MediaPipe 물체 인식(EfficientDet-Lite0, COCO 80종)을 초당 약 6번 돌리고, 손 관절 영역과 겹치는 물건만 "쥔 물건"으로 봅니다. (사람은 제외)
2. **형태와 크기**: 종류를 형태 템플릿으로 바꿉니다. 컵·병·꽃병 → 원기둥, 공·사과·오렌지 → 구, 휴대폰·리모컨·책·마우스 → 상자, 칼·포크·숟가락·칫솔·가위·바나나 → 막대. 실제 크기는 **손을 자로 써서** 계산합니다. (화면 속 손바닥 길이 ↔ 실제 약 9.4cm 비율로 물건 상자 크기를 cm로 환산, 종류별 현실적인 범위로 제한)
3. **손에 앉히기**: 원기둥·굵은 막대는 손바닥 피부에 닿게 검지-소지 방향으로, 구는 손바닥 앞(작으면 집는 손끝 사이), 상자는 뒷면을 손바닥에 대고 긴 변을 가로로(폰을 볼 때 쥐는 방식), 펜 같은 막대를 집으면 엄지·검지 끝을 지나 손가락 사이 물갈퀴 쪽으로 눕힙니다.
4. **표면 부착 보정**: 물건 근처 손가락마다(엄지 포함) 굽힘 비율을 이분 탐색해서 손끝 살(8mm)이 표면에 닿게 맞춥니다. 표면 거리는 원기둥(뚜껑 포함), 구, 회전된 상자 모두 정확한 거리 함수로 계산합니다.
5. **인식이 안 될 때**: 손 모양으로 추정합니다. 네 손가락을 깊고 고르게 감음 → 원기둥, 오목하게 굽힘 → 공, 엄지·검지 끝이 붙음 → 작은 물체. 주먹, 갈고리(귀신 손), 가리키기·브이는 물건 없음. 인식 목록에 없는 물건은 "원기둥/공/상자/막대로 고정"을 고르면 그 형태로 손을 맞춥니다.

### 팔꿈치 (arm.js)

1인칭 구도(폰 = 눈)에서는 팔꿈치가 대부분 화면 아래로 벗어나서, 퀘스트처럼 추정합니다.

- **IK 추정(기본)**: 눈 기준 어깨 위치(옆 18cm, 아래 24cm, 뒤 6cm)에서 손목까지 위팔 29cm·아래팔 26cm 2관절 IK를 풀고, 팔꿈치가 굽는 방향은 손목 뒤로 이어지는 손 방향(손의 -Y)을 따릅니다.
- **포즈 인식**: MediaPipe 포즈 모델이 팔꿈치를 또렷하게(가시도 0.6 이상) 보고, 그 팔의 손목이 추적 중인 손과 맞으면 인식된 팔꿈치 위치를 씁니다. 관절 각도 표의 "팔꿈치" 줄에 "인식" / "IK 추정"으로 출처를 표시합니다.
- 출력: 팔꿈치 굽힘(°), 손목 굽힘·꺾임(°), 아래팔은 손의 회전을 따라 비틀림(회내/회외), Mixamo 이름(`LeftArm`, `LeftForeArm`) 회전.

### 포즈 JSON

```jsonc
{
  "format": "hand-motion-studio.pose", "version": 1, "name": "귀신 손 01",
  "skeleton": { "id": "hms-hand-v1", "naming": "mixamo", "units": "meters", ... },
  "hands": {
    "left": {
      "position": [x, y, z],              // 씬에서 손목 위치
      "wrist":    [x, y, z, w],           // LeftHand 회전
      "bones":    { "LeftHandIndex1": [x, y, z, w], ... },  // 로컬 회전 (바인드 회전 포함)
      "delta":    { "LeftHandIndex1": [x, y, z, w], ... },  // 바인드 자세 대비 회전 (리타게팅용)
      "angles":   { "index": [{ "flex": 39.6, "abd": -15.3 }, ...], ... },   // 사람이 읽는 각도(°)
      "landmarks": [[x, y, z], ...],      // 원본 3D 랜드마크 21개 (보정 전)
      "object": { "type": "cylinder", "label": "컵", "source": "camera", "center": [x, y, z],
                  "radius": 0.037, "axis": [x, y, z], "length": 0.1 },  // 쥔 물건 (손목 기준, 없으면 null)
                  // 상자는 "quaternion", "size": [가로, 세로, 두께]
      "arm": { "source": "ik", "shoulder": [..], "elbow": [..], "wrist": [..],
               "elbowFlex": 47.2, "wristFlex": -10.1, "wristDeviation": 6.3,
               "bones": { "LeftArm": [x, y, z, w], "LeftForeArm": [x, y, z, w] } }   // 씬 좌표
    },
    "right": { ... }
  }
}
```

본 이름은 Mixamo 규칙(`LeftHandThumb1..4`, `RightHandIndex1..4` …)이라 Mixamo 계열 캐릭터로 옮기기 쉽습니다. 뼈는 로컬 +Y 방향, 굽힘은 로컬 +X 회전입니다.

## 알려진 한계

- 손가락 비틀림(twist)은 계산하지 않습니다. 엄지 회전은 근사치입니다.
- 손목 위치의 깊이는 화면상 손 크기로 추정해 절반만 반영합니다.
- 리깅 손 비율은 성인 평균값 고정입니다. (사용자 손 길이 보정은 다음 단계 후보)
- 물건은 원기둥/구/상자/막대 4가지 기본 형태로 근사합니다. 인식할 수 있는 종류는 COCO 80종 중 손에 쥐는 물건(약 25종)이고, 문손잡이·총 같은 것은 목록에 없어 손 모양 추정이나 형태 고정을 써야 합니다.
- 손이 물건을 많이 가리면 인식률이 떨어지고, 크기는 물건이 손과 같은 깊이에 있다고 보고 계산합니다.
- 팔꿈치 IK의 어깨 위치와 팔 길이는 평균값이고, 1인칭 구도에서는 팔꿈치 인식보다 IK 추정이 주로 쓰입니다.
- 물건을 쥐면 손가락이 가려져 MediaPipe 추정이 더 흔들립니다. 실제 촬영으로 판정 기준값을 다듬어야 합니다.
- 손가락이 서로 가리면 MediaPipe 3D 추정 자체가 흔들립니다. 신뢰도 표시와 가동 범위 제한으로 줄이지만 완전히 없애지는 못합니다.
