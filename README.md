# Hand Motion Studio (1단계 프로토타입)

스마트폰/웹캠 카메라로 양손(21관절 x 2)을 추적하고, 랜드마크를 **게임 캐릭터에 바로 쓸 수 있는 관절 회전(쿼터니언)** 으로 바꿔 Three.js 리깅 손 모델에 적용한 뒤, 포즈를 JSON으로 저장/불러오는 웹 앱입니다.

## 실행

**폰에서 바로 쓰기:** https://youngdeukss.github.io/3d-hand/ (GitHub Pages, https라 폰 카메라가 열립니다)

빌드된 `index.html`과 `vendor/`(Three.js, MediaPipe wasm, 손 모델)가 모두 들어 있어 인터넷 없이도 돌아갑니다. 정적 서버로만 열면 됩니다.

```bash
npm install        # esbuild 등 개발 도구 (소스를 고칠 때만 필요)
npm run build      # app.html + src/ -> index.html, dist/artifact/
python3 -m http.server 8080   # 또는 npm start
# 브라우저에서 http://localhost:8080
```

- `file://`로 직접 열면 ES 모듈과 wasm이 막히므로 꼭 서버로 여세요.
- **스마트폰 카메라는 HTTPS에서만 열립니다.** 폰으로 쓰려면 GitHub Pages / Netlify / Cloudflare Pages 같은 HTTPS 정적 호스팅에 폴더째 올리거나, PC에서 `npx localtunnel --port 8080` 같은 터널을 쓰세요.
- 촬영(퀘스트3 방식): 폰을 거치대에 세워 **내 눈 높이에서 내가 보는 방향**을 찍게 하고 "후면 카메라"를 고른 뒤, 폰 뒤에서 양손을 앞으로 뻗습니다. 카메라에 손등이 보이고, 3D 화면도 그대로 1인칭(손등) 시점이 됩니다. 전면 카메라/웹캠처럼 카메라와 마주 보는 경우에는 손을 180° 돌려서 같은 1인칭 화면으로 보여 줍니다. 왼손/오른손이 반대로 붙으면 "왼손·오른손 바꾸기"를 켜세요.

## 화면 구성

- **첫 화면**: "카메라로 시작"(폰은 후면, PC는 웹캠이 기본) 또는 "카메라 없이 데모 보기".
- **실사 겹쳐 보기**(기본 켜짐, 위쪽 "실사" 버튼): 카메라 화면을 배경으로 깔고, 실제 손 위에 반투명한 3D 손·팔을 겹쳐 그립니다. 3D 카메라를 폰 카메라와 같은 위치·화각(긴 변 66°)으로 맞추고, 손목을 카메라 광선 위에 놓아 화면의 손과 겹치게 합니다. 거리는 3D 손 모델이 화면 속 손 크기와 같아지는 값이고, 화면 위치는 거의 지연 없이, 거리는 부드럽게 따로 걸러서 손목이 영상보다 늦게 따라오지 않게 합니다. 끄면 3D 공간 보기(돌려 보기 가능)로 돌아갑니다.
- **메인 화면**: 내 손을 따라 움직이는 1인칭 손·팔 그래픽이 화면을 채웁니다. 아래에는 빨간 **녹화** 버튼과 **리뷰** 버튼만 있습니다.
- **리뷰**: 이번 세션에서 녹화한 테이크를 같은 3D 손으로 다시 재생합니다(재생/일시정지, 위치 이동, 반복). 테이크를 고르고 **GLB 저장**을 누르면 팔·손 뼈대 애니메이션 GLB로 저장됩니다. 테이크는 새로고침하면 사라지니 필요한 건 GLB로 저장하세요.
- **⚙ 옵션**(오른쪽에서 열리는 창): 입력(데모 / 카메라 / 동영상 파일)과 카메라 미리보기, 관절 엔진(가동 범위 제한·손가락별 범위, 떨림 보정, 반응 속도), 팔 표시, 손 재질, 관절 각도 표, 포즈 캡처와 JSON, 마지막 테이크 JSON.
- 동영상 파일을 입력으로 고르고 녹화하면, 처음부터 끝까지 1/30초씩 넘기며 한 프레임씩 처리합니다(기기 속도와 상관없이 30fps).

### 관절 회전 계산 방식 (solver.js)

1. 손목(0)·검지 MCP(5)·중지 MCP(9)·소지 MCP(17)로 손바닥 좌표계를 만들어 손목 회전을 구합니다. (+Y 손가락 방향, +Z 손바닥 법선)
2. 각 뼈마다 관측된 방향(자식 관절 − 관절)을 **이미 풀린 부모 뼈의 기준 자세 좌표계**로 옮깁니다.
3. 그 방향을 굽힘(로컬 X축 회전)과 벌림(로컬 Z축 회전) 두 각도로 분해하고, 해부학적 범위로 자릅니다. (기본값은 임상 가동범위표 기준: MCP 0~90°, PIP 0~100°, DIP 0~90°, 엄지 MCP 0~60°, IP 0~80°. 옵션 → 관절 엔진 → "손가락별 가동 범위"에서 손가락·관절마다 고칠 수 있고 브라우저에 저장됩니다.)
4. 비틀림 없는 회전으로 다시 조립해 `restLocal * swing` 형태의 로컬 쿼터니언을 만듭니다.
5. 뼈 길이가 기준값에서 갑자기 벗어나면(가림, 원근 왜곡) 신뢰도를 낮추고 그 뼈는 더 천천히 따라가게 합니다.
6. **손목은 타원관절(요골손목관절)** 로 다룹니다. 아래팔 기준으로 굽힘 70°, 폄 60°, 엄지쪽(요측) 20°, 새끼쪽(척측) 35° 범위의 타원 안에서만 움직이고, 손목 자체의 비틀림은 0입니다. 손을 뒤집는 회전(회내·회외)은 아래팔 뼈가 맡습니다. 카메라가 본 손 방향이 범위를 넘으면 손이 아니라 아래팔 방향을 돌려 맞춥니다. 팔꿈치는 0~150°의 경첩 관절이라, 위팔의 로컬 X축이 항상 굽힘 축이고 굽힘은 언제나 양수입니다(손바닥이 어느 쪽을 보든 게임 리그에서 팔꿈치가 반대로 꺾이지 않음). 아래팔은 그 위에 회내·회외 비틀림만 더합니다.
8. **손가락 운동 모델**: 가동 범위는 외력으로 밀었을 때의 한계일 뿐, 실제 움직임은 힘줄과 인대가 관절들을 묶어서 늘 비슷한 궤적을 따릅니다. 그래서 추적된 각도에 연동 규칙을 겁니다. 하나의 힘줄이 PIP와 DIP를 함께 굽히므로 DIP는 PIP의 약 2/3를 따르고, 엄지 IP는 MCP를 따릅니다. 첫 마디가 굽을수록 옆 벌림은 사라지고 손가락 끝이 엄지 뿌리(주상골) 쪽으로 모여서, 주먹이 안쪽으로 꼭 쥐어집니다(손 가운데로 모임: 굽힌 끝에서 검지 −5°, 중지 0°, 약지 5°, 소지 10°). 약지·소지·중지는 근육을 나눠 쓰는 이웃 손가락 쪽으로 함께 끌려갑니다(35%·20%·15%).
9. **정확도 우선**: 고정된 손 모양(주먹 템플릿 등)으로 끌어당기지 않습니다. 가동 범위는 손이 할 수 없는 자세만 막고, 범위 밖으로 굽힘 10°, 젖힘 5°, 손가락 첫 마디 옆 벌림 4°까지는 추적된 방향을 그대로 따릅니다. 경첩 관절(PIP·DIP·엄지 IP)은 옆으로 전혀 꺾이지 않고, 대신 첫 마디가 길이 방향으로 최대 12° 돌아서(첫 마디가 30~60° 넘게 굽으면 손끝이 가려져 추정값이 되므로 이 회전은 사라짐) 아래 마디가 자기 평면에서 굽게 합니다. 검지는 엄지 쪽으로 20° 넘게 벌어지지 않습니다. 단, 손허리손가락관절(MCP)이 굽을수록 옆 벌림 허용치(오차 여유 포함)가 cos(굽힘)로 줄어들고, 둘 다 굽은 이웃 손가락은 옆면이 닿을 때까지 서로 붙입니다(손가락은 서로 뚫고 들어가거나 굽힌 채 벌어질 수 없으므로). 그래서 주먹에서 손가락 사이가 뜨지 않습니다. 이 접촉 보정들은 매 화면 프레임마다 해결된 원래 자세에서 다시 계산합니다(보정된 자세를 또 보정하면 누적되어 점점 틀어지므로). 손가락 길이 비율은 손가락이 거의 펴져 있을 때만 학습합니다. 엄지도 같은 원리로, 추적된 네 손가락이 말려 있고 엄지 끝이 그 위에 있으면(엄지가 손바닥을 가로지르거나 굽어 있을 때만, 곧게 선 따봉은 제외) 엄지 IP 마디는 검지, 끝은 중지의 가운데 마디 바깥면에 닿도록 감쌉니다. 뒤에서 보면 주먹 속 엄지는 거의 가려져서 추적값이 손가락 위에 떠 있거나 파묻히기 때문입니다.
10. **손 모델 맞추기 (퀘스트 방식, 기본 켜짐)**: 뼈마다 따로 각도를 읽는 대신, 손가락 하나를 통째로(엄지 7개, 나머지 4개 손가락은 각 5개 각도) 추적점에 맞춥니다(`src/fit.js`, 감쇠 가우스-뉴턴). 비용은 관절 위치 오차(카메라 깊이 방향은 0.45배만 반영), 가동 범위 벽, 힘줄 연동(DIP≈0.67·PIP, 엄지 IP≈0.9·MCP), 굽힐수록 손 가운데로 모임, 첫 마디 회전 억제, 이전 프레임과의 차이(추적이 불확실할수록 더 크게)입니다. 한 점이 튀어도 오차가 손가락 전체로 실제 손처럼 나뉩니다. 실제 영상 기준 화면상 뼈 방향 오차 평균 3.3°→2.6°, 상위 10% 최대 12.3°→6.4°. 옵션에서 끄면 이전 방식으로 비교할 수 있습니다.
9. **손끝 맞닿기**: 추적된 엄지 끝과 다른 손가락 끝이 가까우면(손바닥 길이의 42% 이하) 그래픽 손에서도 두 손끝을 CCD IK로 맞붙입니다. OK 사인, 집기 동작에서 손끝 사이가 뜨지 않습니다.
10. **손가락 마디 길이 맞춤**: 손 모델의 마디 길이를 추적된 손의 비율(손바닥 길이 기준, 0.8~1.25배)에 천천히 맞춰서, 그래픽 손가락이 실제 손가락과 같은 지점에서 굽습니다.
7. 왼손·오른손 표시는 손 모양의 3D 방향(손가락이 손바닥 쪽으로 굽는 방향)으로 먼저 정합니다. 손을 뒤집을 때 인식기 표시가 바뀌어도 손바닥 좌표계가 뒤집히지 않아, 손가락이 뒤로 꺾이지 않습니다.

랜드마크 자체는 One Euro 필터로 먼저 떨림을 줄입니다.

### 쥔 물건 (objects.js, grasp.js) — 현재 꺼져 있음

> 사용자 요청으로 손에 가상 물건을 붙이는 기능과 물체 인식 모델 로딩을 껐습니다. 코드는 남아 있어서 `app.html`의 숨긴 `object-mode` 값과 `main.js`의 모델 로딩을 되돌리면 다시 켤 수 있습니다.

물건 모양을 먼저 알아낸 뒤, 그 표면에 손이 붙는 손 모양을 만듭니다. (손목 기준 좌표계: +Y 손가락 방향, +Z 손바닥 바깥)

1. **카메라 인식**: MediaPipe 물체 인식(EfficientDet-Lite0, COCO 80종)을 초당 약 6번 돌리고, 손 관절 영역과 겹치는 물건만 "쥔 물건"으로 봅니다. (사람은 제외)
2. **형태와 크기**: 종류를 형태 템플릿으로 바꿉니다. 컵·병·꽃병 → 원기둥, 공·사과·오렌지 → 구, 휴대폰·리모컨·책·마우스 → 상자, 칼·포크·숟가락·칫솔·가위·바나나 → 막대. 실제 크기는 **손을 자로 써서** 계산합니다. (화면 속 손바닥 길이 ↔ 실제 약 9.4cm 비율로 물건 상자 크기를 cm로 환산, 종류별 현실적인 범위로 제한)
3. **손에 앉히기**: 원기둥·굵은 막대는 손바닥 피부에 닿게 검지-소지 방향으로, 구는 손바닥 앞(작으면 집는 손끝 사이), 상자는 뒷면을 손바닥에 대고 긴 변을 가로로(폰을 볼 때 쥐는 방식), 펜 같은 막대를 집으면 엄지·검지 끝을 지나 손가락 사이 물갈퀴 쪽으로 눕힙니다.
4. **표면 부착 보정**: 물건 근처 손가락마다(엄지 포함) 굽힘 비율을 이분 탐색해서 손끝 살(8mm)이 표면에 닿게 맞춥니다. 표면 거리는 원기둥(뚜껑 포함), 구, 회전된 상자 모두 정확한 거리 함수로 계산합니다.
5. **인식이 안 될 때**: 손 모양으로 추정합니다. 네 손가락을 깊고 고르게 감음 → 원기둥, 오목하게 굽힘 → 공, 엄지·검지 끝이 붙음 → 작은 물체. 주먹, 갈고리(귀신 손), 가리키기·브이는 물건 없음. 인식 목록에 없는 물건은 "원기둥/공/상자/막대로 고정"을 고르면 그 형태로 손을 맞춥니다.

### 팔꿈치 (arm.js)

1인칭 구도(폰 = 눈)에서는 팔꿈치가 대부분 화면 아래로 벗어나서, 퀘스트처럼 추정합니다.

- **IK 추정(기본)**: 눈 기준 어깨 위치(옆 18cm, 아래 24cm, 뒤 6cm)에서 손목까지 위팔 29cm·아래팔 26cm 2관절 IK를 풀고, 팔꿈치가 굽는 방향은 손목 뒤로 이어지는 손 방향(손의 -Y)을 따릅니다.
- **포즈 인식**: MediaPipe 포즈 모델이 팔꿈치를 또렷하게(가시도 0.6 이상) 보고, 그 팔의 손목이 추적 중인 손과 맞으면 인식된 팔꿈치 위치를 씁니다. 관절 각도 표의 "팔꿈치" 줄에 "인식" / "IK 추정"으로 출처를 표시합니다.
- 출력: 팔꿈치 굽힘(°), 손목 굽힘·꺾임(°), 아래팔은 손의 회전을 따라 비틀림(회내/회외), Mixamo 이름(`LeftArm`, `LeftForeArm`) 회전.

### 포즈 JSON

```jsonc

  "skeleton": { "id": "hms-hand-v1", "naming": "mixamo", "units": "meters", ... },
  "hands": {
    "left": {

      "bones":    { "LeftHandIndex1": [x, y, z, w], ... },  // 로컬 회전 (바인드 회전 포함)
      "delta":    { "LeftHandIndex1": [x, y, z, w], ... },  // 바인드 자세 대비 회전 (리타게팅용)
      "angles":   { "index": [{ "flex": 39.6, "abd": -15.3 }, ...], ... },   // 사람이 읽는 각도(°)
```

### 손과 팔 메시

손 모델(WebXR generic-hand)은 원래 손목이 막혀 있어서, 손목 관절 근처를 평면으로 잘라 열고 한 번 세분화합니다(약 2.3천 → 9.2천 삼각형, 모양을 줄이지 않는 Phong 방식). 팔 메시는 그 손목 테두리 정점을 그대로 첫 줄로 써서 틈이 없고, 손 표면이 향하던 기울기를 이어받아 아래팔 → 팔꿈치 → 위팔 단면으로 넓어집니다(한 바퀴 64정점, 팔 하나 약 7천 삼각형). 손목·팔꿈치는 스킨 가중치가 4~5cm에 걸쳐 섞여서 꺾일 때 부드럽게 휩니다. 화면과 GLB가 같은 메시를 씁니다.

### GLB 내보내기 (exportGlb.js)

포즈의 "GLB" 버튼과 "모션 GLB 저장"은 게임·애니메이션 툴에 바로 넣을 수 있는 glTF 바이너리를 만듭니다. (claude.ai 데모 안에서는 .glb 다운로드가 막혀 있어 같은 파일을 .glb.zip으로 묶어 줍니다.)

```
HMS_ArmsMesh                 스킨 메시: 양손 + 팔 (한 메시, 손목 이음새 없음, 재질 Skin)
Head                         눈 = 폰 위치, 원점. 애니메이션 없음
  FirstPersonCamera          폰과 같은 방향(-Z)을 보는 1인칭 카메라
  LeftShoulder               어깨 위치
    LeftArm                  위팔, +Y가 팔꿈치 방향
      LeftForeArm            아래팔, +Y가 손목 방향, X축이 손을 따라 비틀림(회내/회외)
        LeftHand             손목, +Y 손가락 방향
          LeftHandThumb1..4, LeftHandIndex1..4, ... LeftHandPinky1..4
          LeftHeld_cylinder  쥔 물체 (안 쥐고 있을 때는 scale 0)
  RightShoulder ...          (오른쪽 동일)
```

- 본 이름은 Mixamo 규칙이고 단위는 미터, +Y 위입니다.
- 바인드 포즈는 "두 팔을 앞(-Z)으로 곧게, 손바닥 아래, 손가락 편 상태"입니다. 파일을 열면 첫 프레임 자세로 놓여 있습니다.
- 애니메이션 트랙: 어깨 위치, 위팔·아래팔·손목·손가락 15개 회전(쿼터니언), 쥔 물체의 위치·회전·크기.
- 뼈 길이는 고정입니다(위팔 29cm, 아래팔 26cm). 매 프레임 이 길이로 팔꿈치를 다시 풀고, 추적된 팔꿈치는 굽는 방향으로만 씁니다. 손이 팔 길이보다 멀리 있으면 팔을 늘리는 대신 어깨가 따라 나갑니다.
- 한 번이라도 보인 손의 팔만 들어가고, 중간에 손을 놓친 구간은 마지막 자세를 유지합니다.
- 손 메시는 화면의 실제 손 모델을 내보내기용 뼈대에 다시 붙인 것이라 앱 화면과 같은 모양으로 움직입니다(검증: 손끝·손목·팔꿈치 위치 오차 0.1mm 미만, Khronos glTF Validator 오류 0).

## 알려진 한계

- 실시간 추적은 GPU로 먼저 시도하고, GPU에서 4초 넘게 손을 하나도 못 찾거나 오류가 나면 자동으로 CPU로 다시 시작합니다(일부 폰 GPU는 모델은 돌아가는데 결과가 비어 나옵니다). 화면 위쪽 fps 옆에 GPU/CPU가 표시됩니다.
- 실사 겹쳐 보기의 정렬은 폰 카메라 화각을 66°로 가정합니다. 기기마다 조금 어긋날 수 있습니다.

- 손가락 비틀림(twist)은 계산하지 않습니다. 엄지 회전은 근사치입니다.
- 손목 위치의 깊이는 화면상 손 크기로 추정해 절반만 반영합니다.
- 리깅 손 비율은 성인 평균값 고정입니다. (사용자 손 길이 보정은 다음 단계 후보)
- 물건은 원기둥/구/상자/막대 4가지 기본 형태로 근사합니다. 인식할 수 있는 종류는 COCO 80종 중 손에 쥐는 물건(약 25종)이고, 문손잡이·총 같은 것은 목록에 없어 손 모양 추정이나 형태 고정을 써야 합니다.
- 손이 물건을 많이 가리면 인식률이 떨어지고, 크기는 물건이 손과 같은 깊이에 있다고 보고 계산합니다.
- 팔꿈치 IK의 어깨 위치와 팔 길이는 평균값이고, 1인칭 구도에서는 팔꿈치 인식보다 IK 추정이 주로 쓰입니다.
- 물건을 쥐면 손가락이 가려져 MediaPipe 추정이 더 흔들립니다. 실제 촬영으로 판정 기준값을 다듬어야 합니다.
- 손가락이 서로 가리면 MediaPipe 3D 추정 자체가 흔들립니다. 신뢰도 표시와 가동 범위 제한으로 줄이지만 완전히 없애지는 못합니다.
